# CLAUDE.md

Guidance for Claude Code (and other agents) working in this repository.

## Overview

**Brainbox Runner** (`neverprepared/phantom-runner`) is a **macOS menu-bar app
written in Swift/SwiftUI**. It is the *compute side* of the brainbox
architecture: a central brainbox API acts as orchestrator, and each runner
registers itself, long-polls for work items, and executes them against the
host's Docker daemon, UTM, or a local Ollama instance.

- Bundle ID: `com.neverprepared.brainbox-runner`
- Product: `BrainboxRunner.app` (display name "Brainbox Runner")
- `LSUIElement: true` — menu-bar only, no Dock icon, no main menu
- Deployment target: macOS 13.0 · Swift 5.9
- App sandbox is **off** (needs to spawn `docker` / `osascript`); the
  `com.apple.security.automation.apple-events` entitlement is required and CI
  asserts it is present in the signed binary.

There is **no server component and no MCP server in this repo** — the runner is
purely an HTTP client of the brainbox API plus a set of local process drivers.

## Architecture

### Lifecycle

1. `BrainboxRunnerApp` opens Settings automatically when no API key is in the
   Keychain; otherwise `AppState.startRunnerIfConfigured()` runs.
2. `RunnerCore.start()` builds an `APIClient`, optionally starts the Ollama
   proxy, computes the capability map, and spawns two tasks:
   - **poll loop** — `POST /api/runners/register` (retry every 5s on transport
     failure, abort on 401), then `GET /api/runners/{name}/pending` in a loop
     (long-poll, 40s timeout, `204` = no work).
   - **heartbeat loop** — `POST /api/runners/{name}/heartbeat` with
     `in_flight` / `max_concurrent`; also drains `ResultQueue` + `EnvelopeQueue`.
3. Each work item runs in its own unstructured `Task`, throttled by
   `maxConcurrent` (default 1). Results go to
   `POST /api/runners/{name}/result/{workID}`; undeliverable results are
   persisted and retried with backoff `[5, 15, 60, 300, 1800]`s.

### API endpoints consumed (`APIClient` / `PairingClient`)

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/api/runners/pair/claim` | exchange a pairing token for an API key + URL |
| POST | `/api/runners/register` | announce name, capabilities, tags, version, host, `machine_id`, `ollama_proxy_port` |
| GET | `/api/runners/{name}/pending` | long-poll for the next work item |
| POST | `/api/runners/{name}/result/{workID}` | deliver a result |
| POST | `/api/runners/{name}/heartbeat` | liveness + in-flight count |
| POST | `/api/runners/{name}/event` | best-effort progress telemetry (failures swallowed) |
| POST | `/api/agent_events` | batched (≤50) event-bus envelopes |
| GET | `/api/runners` | reachability probe for Settings → Test connection |
| GET | `api.github.com/repos/neverprepared/phantom-runner/releases` | updater |

### Work kinds handled (`RunnerCore.handle`)

`session.create`, `session.stop`, `session.delete`, `session.exec`,
`session.query`, `integration.up`, `integration.down`, `integration.status`,
`platform.ps`, `platform.action`, `db.list`.

Anything else returns `ok: false, error: "runner not yet implemented for kind: …"`.

- **session.*** — Docker containers (or UTM VMs when `backend: "utm"`).
  `session.create` pulls the image, creates + starts the container, bootstraps
  the agent, and launches `ttyd` on container port 7681 via
  `/home/developer/ttyd-wrapper.sh`. Default TTL 3600s.
- **integration.*** — materializes a `compose_yaml` payload into
  `~/.phantom/integrations/<name>/` and runs `docker compose -p <name>`
  up/down/ps. Names are validated `^[a-z0-9][a-z0-9_-]*$`.
- **platform.*** / **db.list** — inspect/act on the `phantom-platform` compose
  project (default) and list databases on its postgres container. The SQL is
  hard-coded here, never taken from the wire.

Every handler that touches Docker first checks `settings.dockerEnabled`.

### Capabilities

Advertised at registration as a `{String: Bool}` map: **`docker`**, **`utm`**,
**`ollama`**. `ollama` is only advertised as true when the user enabled it *and*
`http://127.0.0.1:11434/` responded — the runner then starts a self-signed
HTTPS proxy on `ollamaProxyPort` (default **11435**) that checks the shared API
key and forwards to local Ollama, so Ollama never has to bind `0.0.0.0`.

### Docker CLI resolution

The app runs as a GUI login item with the bare launchd `PATH`, so `docker` is
resolved by **absolute path**, in order:
`~/.orbstack/bin`, `/usr/local/bin`, `/opt/homebrew/bin`,
`/Applications/Docker.app/Contents/Resources/bin`. Never assume the shell PATH.

## Key commands

The Xcode project is **generated**. Always regenerate before building:

```bash
brew install xcodegen        # once
xcodegen generate            # regenerate BrainboxRunner.xcodeproj from project.yml
```

Build (matches CI exactly):

```bash
xcodebuild \
  -project BrainboxRunner.xcodeproj \
  -scheme BrainboxRunner \
  -configuration Debug \
  -destination "generic/platform=macOS" \
  CODE_SIGN_IDENTITY="" CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO \
  build
```

Local distributable (ad-hoc signed, not notarized):

```bash
./scripts/make-dmg.sh [output-dir]     # default dist/
```

Release: push a `vX.Y.Z` tag. `release.yml` signs with the Developer ID cert,
notarizes via `notarytool`, staples, builds the DMG, and creates the GitHub
Release. Bump `MARKETING_VERSION` (and `CURRENT_PROJECT_VERSION`) in
`project.yml` in the same commit as the tag.

**There are no tests and no linter in this repo.** `project.yml` declares a
single `application` target with no test target, and CI runs a Debug build only.
Do not claim `make test` / `swift test` works — verification here means "the
`xcodebuild` above succeeds". If you add behaviour worth testing, adding a
`BrainboxRunnerTests` unit-test target to `project.yml` is the right move.

Logs (OSLog, subsystem `com.neverprepared.brainbox-runner`, categories
`core`, `docker`, `utm`, `ssh`, `session`):

```bash
log stream --predicate 'subsystem == "com.neverprepared.brainbox-runner"' --info
```

## Conventions

- **`project.yml` is the source of truth**, not the `.xcodeproj`. Add files by
  dropping them under `BrainboxRunner/` and re-running `xcodegen generate` —
  the target uses a directory-based `sources` entry, so no manual project edits.
- `.gitignore` lists `*.xcodeproj/`, yet `BrainboxRunner.xcodeproj/project.pbxproj`
  **is** committed (force-added). If you regenerate it and want the change in,
  you must `git add -f`. Same for `CLAUDE.md`, which a global gitignore excludes.
- All UI-facing state is `@MainActor`; `RunnerCore` and `AppState` are main-actor
  isolated and network work is `async` off the main thread.
- Drivers are `enum` namespaces of `static func`s that shell out via `Process`;
  they never touch UI state.
- Secrets: API key in the **Keychain** only. Never log it, never put it in
  UserDefaults. Log statements use `privacy: .public` deliberately only for
  non-sensitive identifiers.
- Wire types use **snake_case** field names to match the brainbox contract
  (`machine_id`, `ollama_proxy_port`, `in_flight`, `start_at`, …) — keep them
  that way even though it clashes with Swift style.
- Arbitrary JSON crosses the boundary through `AnyDecodable` / `AnyEncodable`
  (payloads/results) and `AnyCodableValue` (envelope metadata).
- Any value that becomes a shell argument, path segment, or compose project name
  is regex-validated before use. Preserve that when adding handlers.
